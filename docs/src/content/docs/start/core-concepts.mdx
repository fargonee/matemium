## Project

A project is the complete workspace for one explanation or closely related
series. It contains creative decisions, source files, imported media, and output
history.

## Description

The description states what the project is trying to communicate. It should
change less often than scene implementation.

## Passport

The passport stores foundational choices such as audience, format, production
path, and communication identity. Changing these decisions can invalidate later
work, so Matemium resolves them early.

## Production path

The selected route through production:

- **Visual-first** — produce a finished mute film for your own sound.
- **Voice synthesis** — write narration, regulate timing, generate speech, and
  assemble the result.
- **Custom voice** — begin with an approved external performance and build the
  visuals against verified audio.

## Roadmap

The roadmap records phases, progress, blockers, and the current production
decision. It is project state—not a generic checklist shown identically for
every workflow.

## Scene

A Python class extending `CanvasScene`. A project can contain more than one scene,
although the desktop normally selects one scene for a render.

## `scenes.py`

The primary authoring file. Humans and the agent edit the same visible Python
source. Matemium does not use generated JSON as the normal authoring format.

## Builder

`CanvasBuilder` is the recommended declarative authoring API. It collects content,
layout intent, world objects, and timeline operations before compiling them into
the internal scene representation.

## Generic data visual

`DataPath`, `DataPlot`, and `Diagram` turn sampled project data into reusable
visual structures. Their named semantic parts can be changed later without
introducing subject-specific engine methods.

## Semantic part

A stable address inside a compound visual, such as
`control_loop::node:sensor`, `response::series:measured`, or
`trajectory::path`.

## State transition and morph

A state transition changes allowlisted visual properties on one or more
elements or semantic parts in a synchronized beat. A morph recompiles target
content and replaces the existing registered visual while preserving its
timeline identity.

## Tape

A tape is a structured 2D content context. The automatic root tape behaves like
an infinite document: content flows vertically, reveals lazily, and remains
addressable after appearing.

Projects can use additional tapes for comparisons or parallel explanations,
but current multi-tape switching is an advanced feature that needs preview
evidence.

## World object

Anything positioned in Matemium’s experimental 3D world path, such as a
registered solid or other free object. Tape-local solids and inspection are the
more mature production method. Arbitrary physical tape placement remains an
unfinished architecture seam.

## Render

A local compilation of a scene through Matemium’s Manim-based engine. Rendering
produces visual evidence that should be inspected rather than assumed correct.

## Visual repair

The loop of rendering, inspecting, identifying a concrete defect, changing the
project, and rendering again.

## Output

Generated videos, images, full-sheet exports, and related delivery artifacts.
Output remains local unless you explicitly publish or move it.
